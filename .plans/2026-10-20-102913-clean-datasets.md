# Clean Datasets

## Goal

Keep prose datasets in four root collections: `human`, `ai-suspected`, `ai-normal`, and `ai-synthetic`. Store text as Markdown with a matching `.labels.json`; retain source attribution, original judgments, and evaluation restrictions.

## Approach

1. Create a strict JSON schema and shared reader in `runners/`. Validate checksums, passage ranges, label types, source metadata, and collection boundaries.
2. Move the existing human and suspected-AI articles byte-for-byte. Place the 400 articles generated for testing under `ai-synthetic`, retaining their recorded models and unknown generation instructions.
3. Combine the 604 holdout paragraphs into one Markdown collection. Preserve identifiers, primary types, original labels, evidence, coverage references, and outstanding review objections in its labels file.
4. Extract prose and usable annotations from generated batches, editor experiments, and externally labeled language datasets. Keep original numerical/categorical linguistic judgments and separate isolated examples by explicit ranges.
5. Remove downloaded packages, lexicons, image ratings, historical model calls, transcripts, reports, and archives from the active datasets. Git retains their previous versions.
6. Update the Jev reader and result snapshot to the new storage, proving that all target text, request hashes, saved scores, and sentence highlights stay identical. Update surviving corpus helpers and remove helpers specific to deleted experiments.
7. Run Specular, paired-dataset validation, contract tests, saved-result comparison, Fixture3, and package validation. Review the migration against original Git data and commit/push on `main`.

## Decisions

- Origin describes authorship or collection purpose. A slop label is an explicit judgment about a named issue and passage; empty labels mean unreviewed.
- A collection may contain independent samples, each with its original identifier and range. Article text remains unmodified; collections preserve each original sample verbatim.
- A no-hit is scoped to its stated check or family. Omitted checks remain unassessed. Holdout controls retain their original family-wide scope.
- Store one checksum per document. Ranges use JavaScript string positions, matching the existing runner and textlint offsets.
- Keep resolved labels and concise unresolved objections beside the affected sample; review transcripts remain in Git history.
- Retain source-license records beside source collections. The existing license index marks some collected documents internal; preserve that designation during this storage change.
- Keep the four prompt files unchanged. Keep model answers in `runners/results`, and remove obsolete readers rather than retaining broken paths or duplicate formats.

## Files

- `datasets/**`: article/collection pairs and one root README replace the old folders.
- `runners/datasets.mjs`, `runners/dataset.schema.json`: shared runtime-validated reader and label contract.
- `runners/jev.mjs`, `runners/results/semantic-thinness-v1.json`, `runners/README.md`: preserve inference and scoring with the new input representation.
- `runners/legacy/**`, `developer-helpers/README.md`, `.gitleaksignore`: repair surviving callers and exact moved-source fingerprints.
- `scripts/datasets-contract.mjs`, `fixture3.yaml`, `behavior/fixtures/datasets/**`, `behavior/golden/datasets/**`: boundary-level regression checks.
- This plan, its Specular JSON, and the completion worklog record intent, verification, and removals.

## Coverage

- Specular checks the four collections, paired holdout, reader/schema, and absence of old dataset roots.
- Contract tests exercise valid inputs, stale checksums, invalid ranges, independent sample boundaries, no-hit scope, and output/input separation.
- Migration checks compare every retained original article and all 604 holdout records against `41d34169`; saved Jev requests and results must reproduce exactly.
