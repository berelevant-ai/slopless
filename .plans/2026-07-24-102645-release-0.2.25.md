# Release 0.2.25

## Goal

Publish every reviewed change after 0.2.24 as Slopless 0.2.25 from `main`,
verify GitHub CI and npm publication, then install and execute the published
package.

## Approach

1. Change `package.json` from 0.2.24 to 0.2.25.
2. Run repository validation, Specular verification, and all Fixture3 suites.
3. Commit and push the release preparation to `fix/what-matters-frame`.
4. Open a pull request to `main` and wait for every required status check.
5. Merge the pull request into `main`.
6. Publish GitHub release `v0.2.25`, which triggers the npm provenance workflow.
7. Verify the release workflow, npm registry version, package provenance, and
   a clean installed CLI.

## Key decisions

- Use a patch release because no public rule ID, export, CLI argument, or
  package interface changed.
- Publish only from the protected `main` branch through the existing GitHub
  release workflow.
- Do not publish directly from the local checkout.
