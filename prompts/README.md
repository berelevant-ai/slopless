# Prompts

- `v1/shared.md` contains the common instructions.
- The three adjacent Markdown files describe the individual checks. The runner supplies the common instructions and one selected check per request.
- Copy a version folder when testing revised wording, then pass its path with `--prompts`. Keep the holdout paragraphs and labels out of prompt examples.
- `v2/` covers the nine consolidated semantic-thinness types. Its shared and generic-realization wording is unchanged from `v1`; the other eight prompts start from the accepted definitions.
- The first balanced development classification run is saved in `runners/results/semantic-thinness-v2-development-classification.json`, with analysis in the adjacent Markdown file.
- `v3/` contains revised missing-actor and unexplained-metaphor prompts plus unchanged shared instructions. The other seven checks retain `v2` wording. Development trials and the selected revisions are saved in `runners/results/semantic-thinness-v3-development-tuning.json`.
- `v4/` contains the tuned generic-realization prompt plus unchanged shared instructions. Its four development trials and selected revision are saved in `runners/results/semantic-thinness-v4-development-tuning.json`; other checks keep their latest wording.
- `v5/` contains the tuned unspecified-change prompt plus unchanged shared instructions. Development trials are in `runners/results/semantic-thinness-v5-development-tuning.json`; the frozen original/new holdout comparison is in `runners/results/semantic-thinness-v2-v5-holdout-comparison.json`.
- `v6/` contains the tuned unspecified-relationship prompt plus unchanged shared instructions. Development trials are in `runners/results/semantic-thinness-v6-development-tuning.json`; the frozen original/new holdout comparison is in `runners/results/semantic-thinness-v2-v6-holdout-comparison.json`.
- `v7/` contains the tuned hollow-significance prompt plus unchanged shared instructions. Development trials are in `runners/results/semantic-thinness-v7-development-tuning.json`; the frozen original/new holdout comparison is in `runners/results/semantic-thinness-v2-v7-holdout-comparison.json`.
- `v8/` contains the tuned empty-takeaway prompt plus unchanged shared instructions. Development trials are in `runners/results/semantic-thinness-v8-development-tuning.json`; the frozen original/new holdout comparison is in `runners/results/semantic-thinness-v2-v8-holdout-comparison.json`.
- `v9/` restores unspecified-scope and circular-explanation to their original `v2` wording after the tuning trial produced zero net holdout accuracy improvement. Rejected candidate snapshots remain in `runners/results/semantic-thinness-v9-development-tuning.json`; their comparison is in `runners/results/semantic-thinness-v2-v9-holdout-comparison.json`.
- `v10/` covers the two consolidated puffery-and-overstatement types. Inflated evaluation selects development revision `r1`; sweeping generalization retains baseline `b0`. The shared instructions explicitly cover multi-paragraph passages. All attempts and the frozen selection are in `runners/results/puffery-and-overstatement-v10-development-tuning.json`; the adjacent Markdown report explains the five development false positives. The [holdout assessment](../runners/results/puffery-and-overstatement-v10-holdout.md) records 99/100 and 100/100 hits caught, with zero false positives for either check.

- `v11/` covers consolidated unsupported authority. Prestige padding selects `prestige-r4` at 99/100 development hits and three false positives; vague attribution selects `vague-r1` at 99/100 and four false positives. The [development report](../runners/results/unsupported-authority-v11-development-tuning.md) records every trial, direct example exposure, and remaining errors; the adjacent JSON preserves the frozen selection and predictions.
- The [v11 holdout assessment](../runners/results/unsupported-authority-v11-holdout.md) records vague attribution at 100/100 hits with five false positives and prestige padding at 99/100 with 23 false positives. Prestige requires a fresh tuning and holdout round before deployment.

- `v12/` contains the staged-opposition baseline and unchanged shared instructions. The assembled prompt is 683 words, with four hit and four no-hit development demonstrations. Independent prompt review and protected holdout repair precede the first development trial.

Run commands are in [runners/README.md](../runners/README.md). Version `v1` preserves the wording from commit `2ebcba5`.
