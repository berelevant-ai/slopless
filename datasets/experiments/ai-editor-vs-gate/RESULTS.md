# Experiment: AI cannot reliably fix AI prose; a deterministic gate can

Date: 2026-05-29. Status: complete. Raw artifacts in this directory.

## Question

Two claims behind the slopless thesis, tested with data:
1. A model asked to remove its own slop, with no deterministic tool, leaves much of it in (correlated blind
   spots). The same model driven by a deterministic gate removes all of it (enforceable guarantee).
2. A deterministic gate gives the same verdict every run and a reachable zero; an AI judge gives a different
   verdict every run and never returns zero.

## Method

- **Model:** Claude Sonnet for every subagent role (generation, blind editor, gate-loop editor, AI judge),
  orchestrated by Opus. Holding the model constant makes the *gate* the only manipulated variable between
  conditions B and C.
- **Inputs (provenance, no circularity):** 6 docs across registers (LinkedIn post, product launch, exec
  strategy memo, wellness article, LLM explainer, brand mission). Each generated by a normal "write polished,
  publication-ready prose" instruction with **zero** mention of slop, slopless, or any pattern. The slop is
  the model's natural default, not text reverse-engineered to trip the rules. 400-500 words each.
- **Conditions:**
  - **A. Baseline** raw generated text.
  - **B. Blind AI editor** a fresh same-model agent told to aggressively remove cliches, buzzwords, filler,
    vacuous sentences, the literal patterns "not just X but Y" / "in today's world" / "it's important to
    note," and stock LLM vocabulary. One rewrite plus one self-review pass. No linter, no tool. This is a
    steelman of "just ask the model to clean it up."
  - **C. Gate loop** a fresh same-model agent running the real slopless CLI, fixing flagged spans, re-running,
    up to 6 iterations.
- **Scoring:** one central slopless run over every output (`analyze.mjs`), so A/B/C are measured identically.
  Findings are bucketed:
  - **slop** emptiness/lexical/rhetorical rules (llm-vocabulary, prohibited-words, negation-reframe,
    triple-repeat, generic-signposting, summative-closer, semantic-thinness, etc.). The headline bucket.
  - **metric** readability thresholds (flesch-kincaid, gunning-fog, coleman-liau, paragraph-length, etc.).
  - **ortho** formatting (sentence-case, smart-quotes, em-dashes, etc.).
  The headline claim rests on the **slop** bucket; metric and ortho are reported for completeness because a
  "remove the slop" instruction does not target a readability score or list capitalization.

## Result 1: blind AI editor vs. deterministic gate (same model)

Findings under one central slopless run:

| Condition | slop | metric | ortho | total |
|---|---|---|---|---|
| A. baseline (raw) | 28 | 14 | 13 | 55 |
| B. blind AI editor | 17 | 13 | 13 | 43 |
| C. gate loop | **0** | **0** | **0** | **0** |

- The blind AI editor removed only **39%** of slop (28 to 17) and barely touched metric/ortho.
- The same model, handed deterministic findings, removed **100%** and reached zero on every bucket.
- The blind editor **introduced** new slop while cleaning: generic-signposting rose 1 to 2, and in the exec
  doc it created a triple-repeated "The goal is..." frame that was not in the source.

The decisive detail: condition B was **explicitly told** to remove "not just X, but Y." It still left, among
others:
- "Early movers are not just picking up efficiency, they are restructuring their cost bases..." (03)
- "a system that has absorbed not just language but the reality language describes" (05)
- "The mistake wasn't skepticism. Skepticism is useful. The mistake was..." (01)
- "These are not theoretical risks. They are already happening..." (03)
- "The goal is not to become an AI company. The goal is to operate..." (03)
- the word "leverage" survived verbatim in the wellness doc (04)

Told exactly what to remove, the model could not reliably find its own instances, because to its own
distribution those constructions are unremarkable. That is a correlated blind spot, measured.

## Result 2: convergence of the gate loop

Per-iteration finding counts (condition C). Iteration-1 counts equal the independent baseline exactly,
cross-validating the harness.

| Doc | per-iteration findings | iterations to zero |
|---|---|---|
| 01-linkedin | 7, 1, 0 | 3 |
| 02-product-launch | 8, 0 | 2 |
| 03-exec-strategy | 13, 3, 0 | 3 |
| 04-wellness | 14, 2, 0 | 3 |
| 05-explainer | 5, 1, 0 | 3 |
| 06-brand-mission | 8, 3, 0 | 3 |

Monotonic descent to a hard zero in 2-3 iterations, every doc. The loop has a fixed point and reaches it fast.

## Result 3: determinism vs. an AI judge (on already-clean text)

Both gate-passed docs (slopless = 0) were re-checked: slopless three times, and a fresh AI judge three times.

| | run 1 | run 2 | run 3 | self-agreement |
|---|---|---|---|---|
| slopless / 03-exec-strategy | 0 | 0 | 0 | 100% |
| slopless / 04-wellness | 0 | 0 | 0 | 100% |
| AI judge / 03-exec-strategy | 14 | 18 | 15 | 33% (8 of 24 distinct items in all 3 runs) |
| AI judge / 04-wellness | 24 | 23 | 21 | 26% (10 of 39 distinct items in all 3 runs) |

- slopless: identical every run; a reachable, certifiable zero.
- AI judge: a different verdict every run, ~two-thirds of its findings non-reproducible (appear in only some
  runs), and it **never returns zero** even on text the gate already cleared. An AI-judge-driven loop has no
  termination signal: it would churn forever, "fixing" phantoms and likely degrading the text.

## Takeaways (for the article)

1. **AI cannot reliably fix AI prose without an external oracle.** Same model, same task; the only difference
   that produced a clean result was the deterministic gate.
2. **The gate's value is the guarantee, not the recall.** It flags fewer categories than an AI judge invents,
   but everything it flags is true and is verifiably eliminated, and absence is certifiable and reproducible.
3. **An AI judge cannot anchor a loop.** No fixed point, no agreement with itself, never returns zero.
4. **It converges fast.** 2-3 iterations to zero in practice.

## Limitations (state these in the article)

- Single model family (Claude Sonnet) for all roles. Cross-model (e.g. one model editing another's slop, or a
  stronger judge) is future work; the correlated-error argument predicts the same shape but should be shown.
- N = 6 docs, one generation per register. Enough for a clear effect, not a statistical study.
- Condition B was a strong single-shot-plus-self-review, not an infinite AI self-critique loop. Result 3 is
  the reason an infinite AI loop does not rescue condition B: the judge has no stable target and never halts.
- Bucket definitions are ours and disclosed above.
- slopless checks ~50 patterns. Zero findings means absence of *those* patterns, not perfect prose. This is
  soundness, not completeness, and is the intended trade.
