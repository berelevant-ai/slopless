## The Tech Stack (Simpler Than You'd Think)

I wanted something fast and maintainable. Here's what I went with:

- **HTML + CSS + Vanilla JavaScript** — no frameworks, no build step
- **Google Analytics** for understanding visitor patterns
- **Schema.org markup** for better SEO
- **Mobile-first responsive design**

That's it. No React, no Webpack, no npm packages (mostly).

**Why no framework?**
- ⚡ Lightning fast page loads
- 🔧 Easy to maintain solo
- 💻 Anyone can read the code on GitHub
- 📦 No build pipeline to break

## Lesson #1: Privacy is a Feature, Not a Nice-to-Have

![Privacy First - Your data never leaves your browser](https://dev-to-uploads.s3.amazonaws.com/uploads/articles/59y6qhc62b27br4g1f46.png)

The biggest realization: **users care about privacy.**

When I made "100% browser-based" the main feature, engagement jumped. People want tools that:
- Don't track them
- Don't store their data
- Work offline once loaded
- Don't require accounts

Here's how I handle JSON formatting entirely client-side:

![JSON Formatter code sample](https://dev-to-uploads.s3.amazonaws.com/uploads/articles/33rswmsav2iu3myz4beh.png)


```javascript
function formatJSON() {
  const input = document.getElementById('jsonInput').value.trim();
  if (!input) return showStatus('Please paste some JSON first.', 'error');

  try {
    const formatted = JSON.stringify(JSON.parse(input), null, 2);
    document.getElementById('jsonOutput').value = formatted;
    showStatus('✓ Formatted!', 'success');
  } catch (e) {
    showStatus('✗ Invalid: ' + e.message, 'error');
  }
}
```

That's the entire JSON formatter. Browser handles everything.

## Lesson #2: Schema.org Markup Made a Huge Difference

After adding JSON-LD structured data, my Search Console impressions doubled.

Here's the markup I add to every tool page:

```html
<script type="application/ld+json">
{
  "@context": "https://schema.org",
  "@type": "WebApplication",
  "name": "JSON Formatter",
  "description": "Free online JSON formatter and validator",
  "applicationCategory": "DeveloperApplication",
  "operatingSystem": "Any (Web Browser)",
  "offers": {
    "@type": "Offer",
    "price": "0",
    "priceCurrency": "USD"
  }
}
</script>
```

Google now shows rich results with my tool name, "Free" badge, and ratings.

## Lesson #3: Building the JWT Decoder Was Fun

JWT decoding in JavaScript is just Base64 + JSON parse. Took 20 lines:

```javascript
function base64UrlDecode(str) {
  str = str.replace(/-/g, '+').replace(/_/g, '/');
  while (str.length % 4) str += '=';
  return decodeURIComponent(escape(atob(str)));
}

function decodeJWT() {
  const token = document.getElementById('jwtInput').value.trim();
  const parts = token.split('.');

  if (parts.length !== 3) {
    return showStatus('Invalid JWT format', 'error');
  }

  try {
    const header = JSON.parse(base64UrlDecode(parts[0]));
    const payload = JSON.parse(base64UrlDecode(parts[1]));

    console.log('Header:', header);
    console.log('Payload:', payload);
    console.log('Signature:', parts[2]);
  } catch (e) {
    showStatus('Invalid: ' + e.message, 'error');
  }
}
```

**Important note for JWT users:** The payload is just Base64 encoded, NOT encrypted. Never store sensitive data in JWT payloads. Anyone can decode them.

## Lesson #5: Mobile-First Was Critical

Over 60% of my visitors are on mobile. So the design HAD to work on small screens.

Key mobile decisions:
- ✅ Hamburger menu for tools navigation
- ✅ Single-column layout on phones
- ✅ Large tap targets (44px minimum)
- ✅ No hover-only interactions
- ✅ Tested on real devices, not just dev tools

If you're building tools today, **start with mobile design.**

## Mistakes I Made

Being honest about the things that went wrong:

### ❌ Mistake 1: Picked a Domain with a Typo
My domain is `jsonformatt.com` — extra "t" in "formatt." Bad for direct traffic.

**Lesson:** Spend time on the domain name. People won't randomly type your URL.

### ❌ Mistake 2: Started Too Fancy
First version had animated backgrounds, gradients everywhere, sidebar navigation. Looked cool, performed badly.

**Rebuild:** Clean, simple, fast. Inspired by [jstoolset.com](https://www.jstoolset.com/).

### ❌ Mistake 3: Tried to Submit to AlternativeTo
Got rejected — they don't accept simple developer tools.

**Lesson:** Read directory rules carefully before spending time on submissions.

### ❌ Mistake 4: Built Tools Before Articles
I should have started with content. Tools alone don't bring traffic; articles do.
