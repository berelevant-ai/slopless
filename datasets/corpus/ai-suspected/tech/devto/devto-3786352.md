### Building a Practical Feature Flag System from Scratch in Python

Feature flags (also called toggles) let you ship code to production behind switches that you can enable or disable at runtime. A solid feature flag system helps you deploy safely, experiment rapidly, and roll back changes without hotfixes. This tutorial walks you through designing, implementing, and operating a robust, production-ready feature flag system in Python with clear code examples, testable components, and practical deployment guidance.

What you’ll build
- A simple yet flexible feature flag store with multiple backends (in-memory, Redis, and a file-based backend for startup).
- A flag evaluation engine that supports:
  - Global on/off switches
  - Percentage-based rollout
  - User/segment targeting
  - Multivariate weighting (for A/B testing)
- A lightweight client wrapper to evaluate flags and fall back safely.
- Observability hooks (metrics, logging) and a basic tester suite.
- A deployment plan and runtime considerations to minimize risk.

Before you start
- Target environment: Python 3.10+ (tests assume 3.11+).
- You’ll need: Python, Pip, and optional Redis if you want the Redis-backed backend.
- Responsibilities: You’ll implement the core logic, tests, and example usage. You won’t need to depend on proprietary services.

1) Design overview
Key components
- FlagDefinition: describes a flag’s properties (name, default, rollout rules).
- Backend: interface for storing and retrieving flag definitions and states.
- InMemoryBackend, RedisBackend, and FileBackend: concrete implementations.
- Evaluator: applies flag rules to determine if a flag is enabled for a given context (user, request, etc.).
- Client: a thin helper to fetch and evaluate flags with a simple API.
- Metrics/Observability: lightweight counters and logs to understand flag behavior.

Rule model
- Enabled: global boolean switch.
- Rollout: percentage of users (0-100) that see the flag enabled.
- Targeting: user or context-based rules (e.g., user_id in segment, region, plan).
- Multivariate: assign weights to variants for A/B testing (optional).
- Salt/Seed: a salt value to ensure stable percentage rollouts across users.

2) Data structures

- FlagDefinition
  - name: str
  - default: bool
  - enabled: Optional[bool]  # overrides default if present
  - rollout_percentage: int  # 0-100
  - targeting: List[TargetRule]
  - multivariate: Optional[List[Tuple[str, float]]]  # variant name and weight
  - salt: str

- TargetRule
  - field: str  # e.g., "user_id", "region", "plan"
  - matches: Callable[[dict], bool]  # function to decide match; for serialization, keep a simple expression system
  - variant: Optional[str]  # for multivariate, assign a variant

Note: For simplicity and portability, implement targeting with a tiny expression system rather than raw code.

3) The backend interface

class Backend(ABC):
  def get_flag(self, name: str) -> FlagDefinition: ...
  def list_flags(self) -> Dict[str, FlagDefinition]: ...

Implementations:
- InMemoryBackend: holds flags in a dict, ideal for tests and local dev.
- FileBackend: stores flags in a JSON/YAML file; reloads on demand.
- RedisBackend: persists flags in Redis; suitable for shared deployments.

4) Evaluator logic

Evaluation steps for a given context (ctx):
- If flag.enabled is explicitly False, return False; if True, return True.
- If rollout_percentage > 0:
  - Compute a stable bucket: hash(ctx_id + flag.name + salt) modulo 100
  - If bucket < rollout_percentage, enable; else disable.
- Apply target rules in order:
  - If any TargetRule matches, enable or assign a specific variant if multivariate is set.
- If multivariate is configured and a variant can be chosen via a deterministic function, select based on ctx attributes and variant weights.

- Backends

```python
### backend.py
from abc import ABC, abstractmethod
from typing import Dict
from .flag_model import FlagDefinition

class Backend(ABC):
    @abstractmethod
    def get_flag(self, name: str) -> FlagDefinition:
        pass

    @abstractmethod
    def list_flags(self) -> Dict[str, FlagDefinition]:
        pass

class InMemoryBackend(Backend):
    def __init__(self, flags: Dict[str, FlagDefinition]):
        self._flags = flags

    def get_flag(self, name: str) -> FlagDefinition:
        return self._flags.get(name)

    def list_flags(self):
        return self._flags
```

- Evaluator

```python
### evaluator.py
import hashlib
from typing import Dict, Any, Optional, List
from .flag_model import FlagDefinition, TargetRule

def _hash_bucket(seed: str, key: str) -> int:
    h = hashlib.sha256(f"{seed}:{key}".encode())
    # use first 8 hex chars for a stable bucket 0-9999
    val = int(h.hexdigest()[:8], 16)
    return val % 100  # 0..99

class Evaluator:
    def __init__(self, backend: 'Backend'):
        self.backend = backend

    def evaluate(self, flag_name: str, context: Dict[str, Any]) -> Dict[str, object]:
        flag = self.backend.get_flag(flag_name)
        if flag is None:
            # Fallback to default
            return {"enabled": False, "reason": "flag-missing"}

        # Explicit enable/disable
        if flag.enabled is not None:
            return {"enabled": bool(flag.enabled), "reason": "explicit-override"}

        # Global default
        if flag.default:
            enabled = True
        else:
            enabled = False

        # Rollout
        if flag.rollout_percentage > 0 and flag.rollout_percentage <= 100:
            bucket = _hash_bucket(flag.name, str(context.get("user_id", "")))  # stable per user
            if bucket < flag.rollout_percentage:
                enabled = True
            else:
                enabled = False

        # Targeting rules
        for tr in flag.targeting:
            value = str(context.get(tr.field, ""))
            if value == tr.value:
                if tr.variant:
                    # If multivariate is configured, could select specific variant
                    enabled = True  # variant selection can be extended
                else:
                    enabled = True
                break

        # Multivariate variant selection (optional)
        variant = None
        if flag.multivariate:
            # Simple weight-based selection: sum hash bucket to pick variant
            bucket = _hash_bucket(flag.name, str(context.get("user_id", "")))
            total = sum(w for _, w in flag.multivariate)
            acc = 0
            for v, w in flag.multivariate:
                acc += w
                if bucket < (acc * 100) / total:
                    variant = v
                    break

        return {"enabled": enabled, "variant": variant, "reason": "evaluated"}
```

- Client usage

```python
### client.py
from backend import InMemoryBackend
from flag_model import FlagDefinition, TargetRule
from evaluator import Evaluator

### Define some flags
flags = {
    "new_checkout": FlagDefinition(
        name="new_checkout",
        default=False,
        rollout_percentage=20,
        targeting=[TargetRule(field="region", value="EU")],
        multivariate=[("A", 0.5), ("B", 0.5)],
        salt="checkout_salt"
    ),
    "beta_dashboard": FlagDefinition(
        name="beta_dashboard",
        default=False,
        enabled=None,
        rollout_percentage=0,
        targeting=[TargetRule(field="plan", value="premium")]
    ),
}

backend = InMemoryBackend(flags)
evalr = Evaluator(backend)

### Example contexts
contexts = [
    {"user_id": "u1", "region": "EU", "plan": "basic"},
    {"user_id": "u2", "region": "US", "plan": "premium"},
    {"user_id": "u3", "region": "EU", "plan": "premium"},
]

for c in contexts:
    res = evalr.evaluate("new_checkout", c)
    print(f"context={c} -> {res}")
```

7) Production considerations

- Data consistency
  - Prefer Redis or a centralized datastore for flag definitions in multi-instance deployments to avoid drift.
  - Consider versioning FlagDefinition and a migration path if you change the schema.

- Performance
  - The evaluation logic is small; caching evaluated results per request can help with high-traffic endpoints.
  - If you rely on per-user bucketing, ensure the hash function is fast and stable; sha256 is fast enough for most apps.

- Observability
  - Emit metrics for:
    - Flag evaluations per hour
    - Percentage of users seeing a flag enabled
    - Distribution of variants chosen in multivariate tests
  - Log decision reasons to help debugging (but avoid logging PII).

- Safety and rollback
  - Start with conservative rollout (low percentage) and monitor.
  - Maintain a clear rollback path by keeping the previous flag state and a health check.

- Security
  - If targeting uses sensitive fields, ensure proper sanitization and access controls.
  - Avoid leaking internal salt or algorithm details in client responses.
