# An Introduction to AI Hub, Part 2: Custom MCP Servers

<p>Welcome back to a series of introductory articles on AI Hub, the new product feature currently in an early access program! (links: <a href="https://evaluation.intersystems.com/Eval/early-access/AIHub">EAP Site</a> for download, <a href="https://github.com/intersystems-community/ai-hub-eap/tree/master">documentation</a>)</p><p>In the last article, we covered how to create agents and agent tools directly in ObjectScript using the new %AI classes. However, sometimes, instead of creating a new agent, you just want to add some custom tools to an existing agent so you can ask your local claude code, codex, copilot or other agent of choice to query your data directly. This is where MCP Servers might come in.</p><p>In this guide, we will walk through how you can create your own MCP Servers to access your data.</p><blockquote><p>Disclaimer: AI Hub is an early access preview, with features likely to change before production releases, any issues identified can be raised as issues on the documentation GitHub repo linked above. The EAP preview is not to be used in production settings.</p></blockquote><h2>A very brief intro to MCP</h2><p>I'm going to keep this brief because there are loads of other good articles on MCP Servers Model context protocol (I recommend starting with <a href="https://community.intersystems.com/post/model-context-procotol-mcp-intersystems-iris-zero-hero">this article</a> from <span class="mention"><span class="mention">@Pietro.DiLeo</span></span> or this <a href="https://www.youtube.com/watch?v=pieK0dog66Q">brilliant introductory video</a> from InterSystems President Don Woodlock).</p><p><strong>Model Context Protocol is a transport protocol allowing external tools to be added to an agent</strong>. There is a discovery 'handshake' where the MCP server sends a list of tools to the MCP Client. After the tools are discovered, the agent can send requests for tool executions, including parameters, to the MCP server, which executes the tool call and returns the result.</p><p>MCP servers can be remote servers, i.e. running on a different machine to a client, this usually uses a streamable http/https connection or Server-Side Events. Or MCP servers can be local servers, i.e. running on the same machine, usually using a stdio connection.</p><h3>An important distinction</h3><p>AI hub allows you to create custom MCP servers within your IRIS environment, allowing agents to access or monitor your IRIS databases, productions and statuses. <strong>It is not a pre-configured MCP server</strong>. </p><p>If you are looking for a developer tool which gives your agent free access to an IRIS environment to speed up development, you may be looking for a pre-configured MCP server. If you are looking to create production MCP servers which are secure, auditable and fit within IRIS's governed security environment, AI Hub is what you are looking for. </p><p>There are many pre-configured MCP servers which provides tools for developing with IRIS, including <a href="https://github.com/intersystems-community/iris-agentic-dev">iris-agentic-dev</a>, an MCP tool and skills library created by <span class="mention"><span class="mention">@tomd</span></span>. This is a separate project from AI Hub, so look out for an article about this! </p><h2>MCP in AI Hub</h2><p>In the previous article, we covered creating agent tools and toolsets, here we will go through how to serve these tools as an MCP server using both HTTP and STDIO. The code covered in this article is available in the ai-hub-dev-template which is a nice place to start if you want to play around with IRIS AI hub.</p><p>Before getting to this though lets, take a look at the architecture of an AI Hub MCP server:</p>

![Image description](https://dev-to-uploads.s3.amazonaws.com/uploads/articles/xjl2trccwf8s9jk6o24n.png)
<p>MCP Clients (blue) communicates with <code>iris-mcp-server</code> to bridge the gap between the MCP calls (discovery and execution) and IRIS. This binary then communicates with an MCP Server web application, defined using <code>%AI.MCP.Service</code> as a dispatch class. This dispatch class then routes the tool calls to ObjectScript tool classes which can then operate on IRIS databases. This diagram skips the reverse routing (returning the tool responses) as well as the initial handshake between the MCP Client and the <code>iris-mcp-server.</code></p><p>There are more details on this architecture in the documentation, but this simplified view covers the key elements that we need to define. These are:<br>1. Tools / Toolsets<br>2. %AI.MCP.Service dispatch class<br>3. MCP Application<br>4. iris-mcp-server configuration<br>5. MCP Client connection</p><p>Lets go through these one by one.</p><h3>1. Tools</h3><p>We define tools or toolsets by extending %AI.Tool or %AI.ToolSet, this was covered in detail in <a href="https://community.intersystems.com/post/introduction-ai-hub-part-1-agents-objectscript" target="_blank" rel="noopener nofollow" aria-label="">Part 1</a>, so I'm going to skip over this.</p><h3>2. Defining the dispatch class</h3><p>To define an MCP Service dispatch class, we just need to extend <code>%AI.MCP.Service</code> and point it at the tools/toolsets we want to include in the <code>SPECIFICATION</code> parameter:</p><pre><code class="language-objectscript">Class Sample.MCPService Extends %AI.MCP.Service
{
    Parameter SPECIFICATION = "Sample.ToolSet";
}</code></pre><p>We could include multiple tool/toolset classes by adding the classes as a comma-separated list, but here we've kept it simple with just one. </p><h3>3. Creating the MCP Application</h3><p>Next up, we create an MCP server application. Like other web applications this can be managed from the management portal, or programmatically with the Security.Applications class. In this case, there is a new MCP server management portal in the Management Portal:</p>

![Image description](https://dev-to-uploads.s3.amazonaws.com/uploads/articles/6o7v1ug1yqlxgzfxbvaj.png)
<p>But everything else will feel familiar to developers creating Web Applications in IRIS. </p>

![Image description](https://dev-to-uploads.s3.amazonaws.com/uploads/articles/i93aw5uul4yootmclev3.png)
<p>The key points are to give an endpoint (e.g <code>/mcp/sample</code>) and the MCP Service Class we created earlier. I won't show the programmatic version, but this can be done with <code>Security.Applications</code>, just set the <code>Type</code> value to <code>18</code> to register it in the MCP Server menu.</p><p>At this point, you can see the JSON description of tools being served at http://localhost:52773/mcp/sample/v1/services. This means it is discoverable by the <code>iris-mcp-server</code> binary, <strong>it is not discoverable directly by an mcp client. </strong></p><h3>4. iris-mcp-server configuration</h3><p>The <code>iris-mcp-server</code> binary takes a configuration file when it is run, this is run with the following command:</p><pre><code class="language-bash">iris-mcp-server -c config.toml run</code></pre><p>We'll get to exactly how this command is actually used in the next section (MCP Client), but for now we are going to focus on the config file.</p><p>The first thing to do when writing your config file is to set your connection to IRIS - this requires the credentials for a gateway-privileged user e.g. CSPSystem, the superserver port used for web-gateway (default 1972) and your MCP endpoints:</p><pre><code class="language-plaintext">[[iris]]
name = "local"
server = { host = "localhost", port = 1972, username = "SuperUser", password = "SYS" }
endpoints = [
    {path = "/mcp/sample" }
]</code></pre><p>Then you have to define your transport. This is done in the <code>[mcp]</code> block.</p><p>For <code>stdio</code>, you just need set the type of transport:</p><pre><code class="language-plaintext">[mcp]
transport="stdio"</code></pre><p>For http/https, you also have to give the host and port:</p><pre><code class="language-plaintext">[mcp]
transport = "http"
host      = "0.0.0.0"
port      = 8080</code></pre><p><strong>This port is a different port to the management portal</strong> and will be used only for this MCP server. This is a common mistake because, although you can find the tool catalog on the management portal port at <a href="http://localhost:52773/mcp/sample/v1/services">http://localhost:52773/mcp/sample/v1/services</a>, to actually connect to the MCP server you have to set a different port to communicate to the <code>iris-mcp-server</code> bridge.</p><h4>Authentication</h4><p>We set the web application to unauthenticated above, but this should be avoided for production use. To add authentication, first set the web application to password authenticated. You can add a username and password or a bearer token to the endpoint:</p><pre><code class="language-plaintext">[[iris]]
name = "local"
server = { host = "localhost", port = 1972, username = "SuperUser", password = "SYS" }
endpoints = [
    {path = "/mcp/sample", username="SuperUser" password="SYS" }
]</code></pre><p>If you are using an HTTP/HTTPS connection, you can also choose to not authenticate here, and instead handle authentication in the requests from the MCP client, this will be shown in the connecting from a client setting below.</p><h4>Other settings</h4><p>There are loads more settings to configure here, like the setting up <strong>OAuth</strong>, using environment <strong>secrets</strong> rather than hard-coding settings, configuring <strong>logging and telemetry</strong> and enabling <strong>smart tool discovery</strong>. To get more details on this, there is a <a href="https://github.com/intersystems-community/ai-hub-eap/blob/master/MCP_Server_Guide.md" target="_blank" rel="noopener nofollow" aria-label="https://github.com/intersystems-community/ai-hub-eap/blob/master/MCP_Server_Guide.md">full guide on the iris-mcp-server usage</a>, but for basic usage you just need to define <code>[[iris]]</code> and <code>[mcp]</code>.</p><h2>5. Connecting from an MCP Client</h2><p>The method for adding an MCP server will differ depending on which client you are using, but in general there will be an option somewhere in your agent customization settings to add an MCP server. For example, to set up an MCP server on GitHub Copilot, type <code>&gt;MCP: Add Server...</code> into the VS Code Search bar, or for Claude Code, you can run <code>claude mcp add...</code>. </p><p>The first option will likely be a choice between stdio or http(s) transport. These have quite different connection methods so lets tackle them individually.</p><h3> </h3><h3>Stdio</h3><p>To use a stdio mcp server, you add <code>/path/to/iris-mcp-server</code> as the executable. The default location for this in a docker container is <code>/usr/irissys/bin</code>.</p><p>You also need to add arguments for the stdio config file <code>config_stdio.toml</code> and the run command:</p><pre><code class="language-plaintext">/usr/irissys/bin/iris-mcp-server -c config_stdio.toml run</code></pre><p>As the authentication is is included in the config file, this is all that is required.</p><blockquote><p>Note, the <code>iris-mcp-server</code> binary has to be on the same machine (or container) as your MCP client!</p></blockquote><h3> </h3><h3>HTTP</h3><p>To connect to a remote HTTP MCP server from an MCP client, you first need to start the iris-mcp-server transport by opening a shell and running:</p><pre><code class="language-plaintext">iris-mcp-server -c config_http.toml run</code></pre><p>Unlike the STDIO connection, this needs to be continuously running for the HTTP connection to be usable.</p><p>With this running, we can then add this server to our MCP client by selecting HTTP as the transport or type, and giving the server URL: http://localhost:8080/mcp/sample.</p><p>If we wanted to set authentication at the MCP connection level (rather than the configuration level detailed above), we use standard HTTP authentication headers, like <code>Basic base64(Username:Password)</code> or <code>Bearer &lt;token&gt;</code>. The following Python snippet shows an example of connecting to an MCP server using Langchain's <code>MultiServerMCPClient</code>:</p><pre><code class="language-python">import base64
from langchain_mcp_adapters.client import MultiServerMCPClient

AUTH_HEADER = base64.b64encode(b"SuperUser:SYS").decode("utf-8")
async def get_tools():
    client = MultiServerMCPClient(
        {
            "minimal": {
                "transport": "http",
                "url": "http://localhost:8080/mcp/sample",
                "headers": {"Authorization": f"Basic {AUTH_HEADER}"},
            }
        }
    )

    tools = await client.get_tools()
    return tools</code></pre><h1> </h1><h1>Conclusions</h1><p>We've reached the end of Part 2 of this series! It has been a long part, so well done if you have got this far.
