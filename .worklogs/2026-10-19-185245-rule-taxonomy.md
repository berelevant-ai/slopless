# Rule Taxonomy

## Summary

- Added `developer-helpers/rule-taxonomy.md` as a nested inventory of all 77 public rules across nine existing families, with examples and sentence/paragraph classifications for semantic judgments.
- Expanded the 36 semantic-thinness patterns and the existing narrative, academic, corporate, and cliche template types. Kept source files, model prompts, datasets, and fixture expectations unchanged.

## Decisions

- Preserve existing family names and public rule IDs. List internal template types beneath their owning rule instead of creating additional public rules.
- Distinguish the evidence a semantic judgment needs from current extraction and reporting behavior. Show mixed-scope rules under one ID and retain their cross-paragraph context requirements.
- Keep document totals, headings, configured terms, and exact-character policies explicit rather than assigning every check to a sentence or paragraph prompt.
- Use existing source definitions and fixtures for examples. Keep holdout text out of the taxonomy so it can inform later prompts without exposing evaluation examples.
